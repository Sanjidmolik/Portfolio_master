## 🚀 Quick Start

```bash
python -m venv .venv
.venv\Scripts\activate            # macOS/Linux: source .venv/bin/activate
pip install -r requirements-dev.txt
copy .env.example .env            # macOS/Linux: cp .env.example .env
```

Edit `.env`: set `SECRET_KEY`, and `ADMIN_USERNAME` / `ADMIN_PASSWORD` for the first admin
(12+ characters, mixed case and a number). Then run:

```bash
flask --app app run --debug
```

- Site: http://localhost:5000
- Admin: http://localhost:5000/admin

After the first sign-in, change the password in **Admin → Security** and remove `ADMIN_PASSWORD` from `.env`.

| Command | What it does |
|---|---|
| `flask --app app create-admin` | Create an admin interactively (no password in `.env`) |
| `flask --app app reset-admin-password` | Reset a forgotten admin password |
| `flask --app app sync-cv` | Re-apply the CV content (profile, experience, education, certificates) |
| `flask --app app github-refresh` | Refresh the cached GitHub data |
| `pytest` | Run the test suite (46 tests) |

## 🔐 Security
- No hardcoded credentials; production refuses to start without `SECRET_KEY`
- scrypt password hashing, login rate limit (5/min), sessions revoked on password change
- CSRF protection on every form, strict Content-Security-Policy with nonces, HSTS in production
- Uploaded images are re-encoded to WebP; CVs and certificates must be real PDFs
- Design settings validated against whitelists; GitHub token used only server-side
- Full report: [Audit.md](Audit.md)

## 🌐 Deployment
1. Set `APP_ENV=production`, `SECRET_KEY`, `DATABASE_URL` (PostgreSQL), `SITE_URL`, and `TRUST_PROXY=1` behind a proxy.
2. `pip install -r requirements.txt`
3. Run `gunicorn app:app` (see `Procfile`) or `waitress-serve --port 8000 app:app` on Windows.
4. Keep `static/uploads/` on a persistent disk, then upload your photo, CV and certificates from the admin.
